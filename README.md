# PHOTO LAB — самостоятельная база знаний

Готовый проект для передачи компании и хранения исходников в GitHub. Не зависит от ChatGPT, Sites, внешней CMS или подписки. Стек: Node.js 24.15+ (ветка 24 LTS), встроенная SQLite, HTML/CSS/JavaScript. Внешних npm-зависимостей нет.


## Открытая демоверсия GitHub Pages

Папка `docs/` содержит самостоятельное статическое демо. Для Pages выберите ветку `main`, каталог `/docs`. Оно показывает регламенты, тестирование и кабинет: логин `admin`, пароль `PhotoLabDemo2026!`. Это общедоступные демонстрационные данные, а не защита настоящего кабинета.

Поля редактора, добавление/удаление материалов и выбор правильного ответа работают только с черновиком в памяти вкладки. «Сохранить изменения» всегда выводит ошибку с предложением разместить серверную версию. Сайт и его JSON не меняются. Обновление страницы сбрасывает черновик и демонстрационный вход.

Основная версия в `public/`, `src/` и `scripts/` по-прежнему предназначена для Node.js-хостинга и сохраняет изменения в SQLite. Пароль настоящего администратора задаётся при установке, отдельно от демо.

## Возможности

- Сотрудники читают регламенты и проходят тесты без входа.
- Шесть ролей: фотограф, печатник, продажник, старший смены, управляющий, офис.
- Для каждой роли — вкладки «Регламент» и «Тестирование».
- Поиск по текстам всех ролей, тематические фильтры и подсветка.
- На ПК правила раскрываются в одном списке аккордеонов, без пустых ячеек двухколоночной сетки.
- Боковая панель на ПК сворачивается до узкой полосы с иконками. На телефоне открывается как выдвижное меню.
- Кабинет `/admin`: логин и пароль, создание/редактирование/удаление пунктов и вопросов для любой роли, выбор правильного ответа и пояснения.
- «Сохранить изменения» записывает общую базу сразу, без пересборки сайта. Открытые страницы читателей проверяют обновления каждые 10 секунд и при возвращении во вкладку.
- Проверка теста происходит на сервере. Итог показывает балл, правильные варианты и пояснения. Результаты прохождения не сохраняются и не привязаны к сотрудникам.
- JSON можно скачать для резервной копии или загрузить в черновик администратора. Импорт обновляет общую базу только после сохранения.

В начальном наполнении — все предоставленные пункты фотографа (6.1–6.10, 11 карточек) и 12 вопросов по ним. Для остальных ролей нет исходных материалов, поэтому их разделы и тесты пока пусты; администратор может их наполнить. Исходник: документ «Тестовое задание», раздел 6. Вопросы составлены по этому тексту.

## Быстрый запуск

1. Установите Node.js версии 24.15 или новее в ветке 24.
2. Распакуйте проект и откройте терминал в папке с `package.json`.
3. Создайте администратора:

   ```sh
   npm run admin -- admin
   ```

   Введите пароль из 12–128 символов и повторите его. Ввод скрыт. Готового пароля в проекте нет.

4. Запустите сайт:

   ```sh
   npm start
   ```

5. Откройте `http://127.0.0.1:4173`. Кабинет — `http://127.0.0.1:4173/admin`.

`npm install` не требуется: используются только встроенные модули Node.js. JSON начального наполнения находится в `src/seed.json`. После первого запуска источником актуальных данных становится SQLite; изменения seed-файла не перезаписывают существующую базу.

## Работа администратора

1. Войдите в `/admin`.
2. Выберите «Регламенты» или «Тестирование», затем нужную роль.
3. Выберите материал в списке либо нажмите «Добавить пункт» / «Добавить вопрос».
4. Для правила задайте уникальный номер, название, тему и текст. Абзацы вводятся с новой строки.
5. Для вопроса введите текст и от 2 до 6 вариантов с новой строки. Выберите правильный вариант в списке; при необходимости добавьте пояснение и ссылку на номер пункта.
6. Нажмите «Сохранить изменения». До этого изменения остаются только черновиком в текущей вкладке.

Если другой администратор или вкладка уже сохранили новую версию, сервер не перезапишет её устаревшим черновиком. Скачайте свой JSON, нажмите «Обновить из базы» и перенесите нужные правки. Перед закрытием несохранённого черновика браузер предупреждает.

Один администратор предусмотрен для прототипа. Пароль можно сменить в кабинете. Если пароль забыт, на сервере повторите `npm run admin -- нужный_логин`: эта команда создаст/обновит учётную запись и завершит все прежние сессии. Удалённой публичной регистрации нет.

## Хостинг компании

GitHub используется для исходников. GitHub Pages не запускает серверную часть, поэтому для кабинета и базы нужен VPS, Docker или хостинг с поддержкой Node.js и постоянного диска.

Для production задайте переменные окружения на хостинге:

```text
NODE_ENV=production
APP_ORIGIN=https://knowledge.company.example
HOST=127.0.0.1
PORT=4173
DB_PATH=/var/lib/photo-lab/photo-lab.sqlite
TRUST_PROXY=1
```

- `APP_ORIGIN` — точный адрес сайта без завершающего `/`. Production без этой переменной не запускается.
- Перед Node.js разместите HTTPS reverse proxy (например, Nginx). Proxy должен перезаписывать `X-Forwarded-For`, а Node-порт не должен быть доступен извне. Только при таком proxy задавайте `TRUST_PROXY=1`; иначе оставьте `0`.
- В Docker используйте `HOST=0.0.0.0` и ограничьте опубликованный порт loopback на сервере (`127.0.0.1:4173:4173`).
- Каталог `DB_PATH` должен быть на постоянном диске и доступен процессу для записи. Эфемерная файловая система serverless-хостинга не подходит.
- `.env.example` — образец. Для локального чтения `.env` можно запускать `node --env-file=.env src/server.js`; `npm start` читает переменные самого окружения, а не файл автоматически.

### Пример Nginx

В существующий HTTPS `server` для домена добавьте:

```nginx
location / {
    proxy_pass http://127.0.0.1:4173;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
    client_max_body_size 512k;
}
```

TLS-сертификат и запуск процесса после перезагрузки (systemd, Docker или панель хостинга) настраивает компания.

### Docker

```sh
docker build -t photo-lab .
docker volume create photo-lab-data
docker run --rm -it -v photo-lab-data:/app/data photo-lab node scripts/admin.js admin
docker run -d --name photo-lab --restart unless-stopped \
  -p 127.0.0.1:4173:4173 -v photo-lab-data:/app/data \
  -e NODE_ENV=production -e APP_ORIGIN=https://knowledge.company.example \
  -e TRUST_PROXY=1 photo-lab
```

Команды Docker приведены для shell на Linux. Для bind mount заранее настройте права записи пользователя `node` (UID 1000). Внешний proxy завершает HTTPS. Контейнерную сборку в текущей среде не проверяли.

## Хранение и резервное копирование

Все изменения, учётная запись администратора, сессии и лимит попыток входа находятся в `data/photo-lab.sqlite` по умолчанию. Каталог `data/` исключён из Git. Не размещайте рабочую базу, пароли и `.env` в репозитории.

Перед обновлением исходников сохраните постоянный каталог базы. Для полной файловой копии остановите процесс и скопируйте SQLite вместе с файлами `-wal` и `-shm`, если они присутствуют. JSON из кабинета содержит регламенты и правильные ответы тестов, но не пароль или сессии.

## Защита

Пароль хранится как salted scrypt-хеш, сессия — серверная, cookie имеет `HttpOnly` и `SameSite=Strict` (в production также `Secure`). Запись проверяет сессию администратора, Origin и CSRF-токен; вход ограничен десятью попытками за 15 минут с одного IP. Смена пароля отзывает все сессии. SQL использует параметры, а интерфейс выводит пользовательские тексты через `textContent`.

По вашему требованию чтение и тестирование открыты без авторизации. Кабинет отдельно защищён. Срок сессии — 8 часов. Смена логина и восстановление пароля выполняются серверной командой администратора.

## Проверки

```sh
npm test
```

Проверены гостевой просмотр, запрет записи без входа, CSRF и Origin, cookie, сохранение после перезапуска, конфликт версий, серверная проверка тестов, смена пароля, выход и лимит входа. Интерфейс проверен в Chrome на ПК и на экране 390 px.

## Файлы

- `public/` — интерфейс базы знаний и кабинета.
- `src/server.js` — HTTP-сервер и API.
- `src/store.js` — SQLite, валидация, пароли.
- `src/schema.sql` — таблицы базы.
- `src/seed.json` — начальные регламенты и тесты.
- `scripts/admin.js` — создание/сброс администратора.
- `tests/server.test.js` — проверки API.
- `Dockerfile` — вариант запуска на хостинге.
